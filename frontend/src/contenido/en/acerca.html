02

Why it exists

Cero comes out of a concrete student annoyance: to stand up a web application in Java you had to set up a Tomcat. Package a WAR, deploy it into a container, wrestle with web.xml, and wait for the server to boot every time you changed a line. For a class assignment, for a quick test, for anything small, all of that is overhead.

The question was simple: what if the server came inside? So one was written. 4,481 lines of HTTP/1.1 server on top of the Java standard library: request parsing, headers, chunked bodies, reloadable TLS, multipart, gzip, static files with ranges, WebSocket and SSE. One virtual thread per connection, which is what lets a model this direct hold up.

The result is that java -jar and it is running. No Tomcat, no web.xml, no deployment step.

And the name

This framework has been called three things, and the first two were chosen by elimination. LuxCore clashed with a PHP framework in the same environment and the two were constantly confused. Corvo —raven— fixed the confusion and kept the «cor» of LuxCore, which in Latin is heart, the same root as core: a correct name, but one that said nothing about the framework.

Cero does say something. It is Spanish for zero: zero runtime dependencies, zero configuration to boot, zero servlet container, zero frontend build step if you do not want one. It is not a metaphor that needs explaining — it is the list of things this framework does not make you have. The name and the first line of the README now say the same thing.

It is written Cero, capitalised, even mid-sentence: it is an ordinary Spanish word and lowercase it vanishes into the text. Artifacts and commands stay lowercase, as always: cero-core, cero new.

Coming from LuxCore or from Corvo, the guide is at Migrating and the same script accepts both. And there is no rush: Maven artifacts are immutable, so the applications you do not migrate keep working exactly as they did.

What state it is in

Cero is at 0.5.0, and it is worth saying plainly what that means.

State
Test suite1,584 green, on macOS and on Linux, against real PostgreSQL and MySQL
Continuous integrationJDK 21 and 25, on every change
Runtime dependenciesZero
Applications in productionSix, all ours
Published to Maven CentralNot yet — hence the installer
What is not settled

The HTTP parser is young. It is the surface facing the internet and the one that takes the most punishment: until it has miles on it under real traffic and sustained bursts, calling it mature would not be honest.

And the performance figures were measured in Docker Desktop, inside a virtual machine. The conditions were identical for every framework compared, so the comparison is fair; the standalone numbers have to be repeated on bare metal before being quoted anywhere.
