01

Rutas

@Route sobre la clase fija la base; los verbos sobre los métodos añaden el resto. Una regla, sin excepciones: un valor vacío mapea a la ruta base.

AnotaciónRuta resultanteNota
@Route("/api/tareas")/api/tareasBase de la clase
@Get/api/tareasValor vacío = la base
@Get("/{id}")/api/tareas/{id}Variable de ruta
@Get("/{id}/notas/{n}")…/{id}/notas/{n}Varias variables
@Get("/archivos/*")/api/tareas/archivos/*Comodín, solo al final
@Post @Put @Patch @Delete—Mismo criterio
  • Lo literal gana a lo variable. /tareas/nueva se resuelve antes que /tareas/{id}, sin importar el orden en que se declaren.
  • Sin @Route, la base sale del nombre de la clase: ReporteController → /reporte.
  • Las rutas duplicadas fallan al arrancar, no en la primera petición.
  • 405 con Allow. Si la ruta existe pero el verbo no, la respuesta enumera los verbos válidos.
  • HEAD se resuelve contra GET automáticamente, sin cuerpo.

Rutas sueltas, sin controlador

LambdasJava
.routes(r -> r
    .get("/salud", ctx -> "ok")
    .get("/version", ctx -> Map.of("version", "0.6.0"))
    .post("/eco", ctx -> ctx.bodyText()))

Inyección

Marca un servicio con @Service y se construye la primera vez que alguien lo pide. Los controladores lo reciben con @Inject, por campo o por constructor.

ServiciosJava
@Service
public class Catalogo {
    @Inject Repositorio repositorio;      // por campo
}

@Service
public class Facturas {
    private final Catalogo catalogo;
    @Inject Facturas(Catalogo catalogo) {   // por constructor
        this.catalogo = catalogo;
    }
}

// o a mano, útil para sustituir en pruebas
Cero.app().service(Reloj.class, () -> Instant.now())
  • Los servicios son singleton: una instancia por aplicación.
  • Se registran también por sus interfaces, así que puedes pedir el contrato.
  • Las dependencias circulares se detectan y el error nombra la cadena completa.

public record Tarea(
        @Id long id,
        @Required @Length(min = 3, max = 120) String titulo,
        @OneOf({"baja", "media", "alta"}) String prioridad) {}

// una regla propia
public class Ruc implements Rule<String> {
    public boolean test(String v) { return v.length() == 11 && v.startsWith("20"); }
    public String message()    { return "no es un RUC válido"; }
}

06

Errores

Lanza HttpException con el estado que quieras, o registra un manejador con @OnError para una excepción de tu dominio.

Manejo de erroresJava
@Get("/{id}")
public Object ver(@Path("id") long id) {
    Tarea t = tareas.findById(id);
    if (t == null) throw new HttpException(404, "no existe la tarea " + id);
    return t;
}

@OnError(SaldoInsuficiente.class)
public Object saldo(SaldoInsuficiente fallo) {
    return Result.json(Map.of("motivo", fallo.getMessage())).status(422);
}
Las excepciones no controladas nunca filtran detalles

Cualquier excepción que no sea HttpException devuelve un 500 con el mensaje genérico «error interno». La traza va al ErrorReporter, no a la respuesta.

07

Clase base opcional

Un controlador de Cero no hereda de nada: es una clase normal con anotaciones, y el Context llega por parámetro cuando hace falta. Si un controlador lo usa en casi todos sus métodos, puedes heredar de Controller y ahorrártelo.

Con la baseJava
@Route("/panel")
public class PanelController extends Controller {

    @Get("/perfil")
    public Result perfil() {
        if (!autenticado()) return redirect("/auth/login");
        return view("perfil", Map.of("usuario", usuario().name()));
    }

    @Get("/informe/{id}")
    public Result informe() {
        var informe = informes.porId(param("id"));
        if (informe == null) throw fallo(404, "no existe");
        return json(informe);
    }
}

Trae param, query, form, header, cookie, body, session, usuario, autenticado, y del lado de la respuesta view, json, text, html, redirect, created, noContent, status y fallo. Para todo lo demás, ctx() devuelve el Context entero.

Es opcional de verdad. Los dos estilos conviven en la misma aplicación: quien no hereda sigue recibiendo el Context por parámetro y no se entera de que esto existe.

Por qué no guarda la petición en un campo

Del controlador hay una sola instancia, compartida por todas las peticiones, y Cero atiende cada conexión en su propio hilo virtual. Un campo con la petición dentro sería una carrera: dos peticiones a la vez se lo pisarían y una acabaría respondiendo con los datos de la otra. Por eso las ayudas leen de un portador por hilo. Hay una prueba que lanza 200 peticiones simultáneas y comprueba que cada respuesta trae lo suyo; con un campo compartido, falla.

Sesiones y acceso

La sesión se pide del contexto. Nace cuando se usa por primera vez, y la cookie sale HttpOnly, SameSite=Lax y Secure si la petición venía por HTTPS.

SesiónJava
Session sesion = ctx.session();
sesion.set("usuario", correo);
String quien = sesion.get("usuario", String.class);
sesion.invalidate();                     // al salir
Rota el identificador al identificarte

El identificador que el visitante tiene antes de entrar no puede seguir valiendo después: quien lo hubiera fijado en su navegador se quedaría con una sesión autenticada. Es fijación de sesión, y se evita con una línea: 

if (Passwords.matches(clave, usuario.hash())) {
    ctx.session().regenerateId();        // ← justo aquí, antes de guardar nada
    ctx.session().set("usuario", usuario.correo());
}

Conserva el contenido —incluido el token CSRF—, a diferencia de invalidate(), que lo borra todo.

Las contraseñas se guardan con Passwords: PBKDF2-HMAC-SHA256 a 210 000 iteraciones, sal por contraseña y comparación en tiempo constante. El formato lleva dentro el coste, así que se puede subir sin invalidar lo guardado.

ContraseñasJava
String guardado = Passwords.hash(clave);
boolean vale = Passwords.matches(clave, guardado);
if (Passwords.needsRehash(guardado)) {   // subió el coste desde que se guardó
    usuarios.actualizarHash(id, Passwords.hash(clave));
}

Y para entrar con Google, Microsoft o GitHub, OAuth trae el flujo completo con PKCE y verificación de la firma del id_token.

OAuth 2.0Java
OAuth google = OAuth.google(id, secreto, "https://mi-sitio/auth/google/vuelta");

@Get("/auth/google")
public Result entrar(Context ctx) {
    return Result.redirectExternal(google.autorizar(ctx).url());
}

@Get("/auth/google/vuelta")
public Result vuelta(Context ctx) {
    var identidad = google.intercambiar(ctx);
    ctx.session().regenerateId();
    ctx.session().set("usuario", identidad.correo());
    return Result.redirect("/panel");
}
El estado no es decoración

autorizar(ctx) guarda en la sesión el verificador de PKCE y un estado al azar; intercambiar(ctx) los recupera, compara el estado con el que trae el proveedor en tiempo constante y lo borra antes de canjear el código.

Sin esa comprobación existe un ataque concreto: alguien inicia el flujo con su cuenta, se queda con el código y hace que la víctima visite la URL de vuelta. La víctima acaba dentro de la sesión del atacante y todo lo que guarde ahí —una dirección, un documento, una tarjeta— queda en una cuenta ajena. Por eso el paso está dentro del framework y no en el ejemplo que cada uno copia.

Para varias instancias o para que las sesiones sobrevivan al despliegue, el almacén va a una tabla. Con el de memoria —el de por defecto— cada despliegue echa a todo el mundo.

Sesiones compartidasJava
ServerOptions.builder()
    .sessionStore(JdbcSessions.of("cero_sesiones").createTable())
    .sessionMaxLifetime(Duration.ofHours(12))   // tope de vida, no solo inactividad
    .build();

Tareas y caché

Trabajo fuera de la petición: lanzar y olvidar, esperar un resultado, repetir cada tanto o seguir una expresión cron. Cada tarea corre en su propio hilo virtual, así que bloquearse dentro no cuesta un hilo del sistema.

TasksJava
Tasks tareas = Tasks.start();

tareas.run(() -> correo.enviar(aviso));                  // y olvidarse
var futuro = tareas.submit(() -> informe.generar());       // con resultado
tareas.every(Duration.ofMinutes(5), () -> sondear());
tareas.cron("0 3 * * *", () -> respaldo());                // a las 3 de la mañana

Y para lo que cuesta calcular y cambia poco, una caché con caducidad por entrada:

Cache y EventsJava
Cache<String, List<Noticia>> portada = Cache.of(Duration.ofMinutes(10));
List<Noticia> ultimas = portada.get("portada", clave -> noticias.ultimas(6));

// Bus de eventos: quien publica no sabe quién escucha.
eventos.publish(new NoticiaPublicada(id));

@Listens
public void alPublicar(NoticiaPublicada evento) {
    portada.invalidate("portada");
}

Metrics cuenta peticiones y tiempos por ruta, con percentiles, y sabe escribirse en el formato que lee Prometheus.

ObservabilidadJava
Metrics metricas = Metrics.enabled().ignore("/estaticos");

Cero.app()

   .use(metricas)
   .use(AccessLog.combined())
   .routes(r -> r.get("/cero/metrics", metricas.endpoint()))
   .start();

OpenApi describe las rutas registradas —parámetros, tipos, qué exige autenticación— sin anotar nada aparte. Sirve para generar el cliente TypeScript del frontend a partir del servidor, en vez de escribirlo dos veces.

Detrás de un proxy

Cero habla HTTP/1.1. Para HTTP/2, HTTP/3 y certificados automáticos se le pone delante nginx o Caddy, que además absorbe las conexiones lentas. Es la forma recomendada de desplegarlo.

Dos cosas que hay que declarar

Detrás de un proxy, la petición llega desde el propio proxy y en texto plano. Si no se le dice, la aplicación se cree que nadie usa HTTPS —y no marca la cookie de sesión como Secure— y ve a todo el mundo con la misma dirección, con lo que el limitador de peticiones cuenta a todos juntos y el primero que llegue al tope bloquea el sitio entero. 

ServerOptions.builder()
    .behindProxy(true)                  // hace caso a X-Forwarded-Proto
    .trustProxy("127.0.0.1", "::1")       // y a X-Forwarded-For, solo desde ahí
    .build();

La lista de confianza no es opcional ni cosmética: creerse esas cabeceras vengan de donde vengan deja que cualquiera diga que es otra dirección, y con eso se salta el limitador y se ensucian los registros.

Y los estáticos con su directiva de caché, que si no el navegador revalida de más:

EstáticosJava
StaticFiles.from(raiz, "/medios")
    .cacheControl("public, max-age=3600");

// Para recursos con huella en el nombre — estilo.a1b2c3.css — se puede ir a por todas:
StaticFiles.fromClasspath("estaticos")
    .cacheControl("public, max-age=31536000, immutable");
12

Con React, Svelte o Vue

Cero no te obliga a usar su motor de plantillas. Puede servir JSON y nada más y dejar que el frontend lo pinte, que es lo normal hoy. Las dos formas conviven en la misma aplicación: unas rutas devuelven vistas y otras JSON.

En desarrollo · dos servidores

El frontend en su servidor —5173 para Vite, 3000 para Next— y Cero en el suyo. Como son orígenes distintos, hay que abrir CORS para ese puerto y solo para ese:

DesarrolloJava
Cero.app()
   .use(Cors.allowing("http://localhost:5173"))
   .controllers(ApiController.class)
   .start();

En producción · un solo artefacto

Se compila el frontend, su salida se copia a los recursos, y sale un jar que sirve las dos cosas. Sin nginx delante para unirlos, sin dos despliegues.

Un jar con todoJava
Cero.app()
   .controllers(ApiController.class)          // /api/... devuelve JSON
   .fallback(StaticFiles.fromClasspath("front").spa()
                        .cacheControl("public, max-age=31536000, immutable"))
   .start();
Qué hace spa() y por qué hace falta

Una aplicación que enruta en el cliente —React Router, el router de Svelte— no tiene un archivo por ruta: solo existe index.html. Sin spa(), entrar directo en /panel/usuarios/7 daría 404 y la aplicación solo funcionaría navegando desde la portada.

Con spa(), una ruta que no existe como archivo devuelve el index.html y el navegador decide qué pintar. Pero solo para rutas de página: un .css o un .png que falten siguen dando 404 — devolverles el HTML de la portada convierte un error evidente en uno que se tarda una hora en encontrar.

Si tu frontend genera un archivo por ruta —la exportación estática de Next.js, Astro, Hugo—, no hace falta spa(): /nosotros encuentra nosotros/index.html por su cuenta.

Cómo queda el proyecto

EstructuraTexto
mi-proyecto/
├── backend/            # Cero — Maven, Java 25
│   ├── pom.xml
│   └── src/main/
│       ├── java/...
│       └── resources/front/     # ← aquí se copia lo compilado del frontend
└── frontend/           # React, Svelte, Vue, lo que sea
    ├── package.json
    └── src/...

El paso de copiar la salida del frontend a resources/front/ lo hace tu guion de compilación o el maven-resources-plugin. A partir de ahí, mvn package y tienes un jar con todo dentro.

13

Tiempo real

Dos formas, y casi siempre quieres la primera.

Eventos del servidor · una dirección

El servidor manda cuando hay algo, en vez de que el navegador pregunte cada dos segundos. Es HTTP normal: atraviesa proxies sin configurar nada y el navegador se reconecta solo. Para un panel, un progreso o un aviso, es exactamente lo que hace falta.

ServidorJava
@Get("/eventos")
public void eventos(Context ctx) throws InterruptedException {
    try (Sse eventos = Sse.open(ctx.response())) {
        while (eventos.abierto()) {
            eventos.send(Json.write(metricas.snapshot()));
            Thread.sleep(1000);
        }
    }
}
NavegadorJavaScript
const eventos = new EventSource('/eventos');
eventos.onmessage = e => pintar(JSON.parse(e.data));
Por qué el bucle no es un problema

Ese while deja el hilo dentro mientras el panel esté abierto. Con hilos del sistema sería inviable —cien paneles, cien hilos bloqueados—, pero Cero atiende cada conexión en su propio hilo virtual: cien paneles son cien hilos virtuales, que cuestan unos cientos de bytes cada uno. Es la razón por la que aquí se puede escribir código que bloquea sin pagar por ello.

El panel de este sitio lo usa: los números que ves los empuja el servidor cada segundo.

WebSocket · las dos direcciones

Cuando el navegador también tiene que hablar — un chat, un editor compartido, un juego. Cuesta un protocolo aparte y un proxy configurado; si solo necesitas recibir, no lo uses.

WebSocketJava
.routes(r -> r.ws("/chat", socket -> {
    socket.onMessage(texto -> socket.send("eco: " + texto));
    socket.onClose(() -> log.info("se fue"));
}))
Solo el mismo origen, y no es opcional

Un WebSocket lleva las cookies del sitio y la política del mismo origen del navegador no lo protege: sin comprobar nada, cualquier web que visite un usuario puede abrir un canal contra tu aplicación con la sesión de ese usuario y leer lo que salga por él. Es CSRF, pero con respuesta.

Cero compara Origin con Host en el apretón de manos y responde 403 si no coinciden. Un cliente que no es un navegador no manda Origin y pasa: esa cabecera la pone el navegador y el JavaScript de la página no puede cambiarla, así que su ausencia significa que no hay ninguna página de por medio.

Si el frontend vive en otro dominio, o si un proxy inverso reescribe Host con la dirección interna, declara los orígenes: WebSockets.accept(peticion, respuesta, manejador, Set.of("https://app.pe")). El 403 nombra los dos valores que comparó, para que eso no se depure a ciegas.

Sobre «programación reactiva»

Cero no tiene Flux, Mono ni nada parecido, y es una decisión. Ese estilo existe para no bloquear hilos del sistema, que son caros. Con los hilos virtuales de Java 21 dejan de serlo: puedes escribir código normal, de arriba abajo, que bloquea — y el rendimiento es el mismo sin el coste de encadenar operadores ni de depurar trazas de pila ilegibles. Es la misma capacidad, por otro camino.

Varios idiomas

Los textos van en .properties del classpath: uno base y uno por idioma.

src/main/resourcesArchivos
mensajes.properties        # el idioma base
mensajes.en.properties
mensajes.qu.properties
ArranqueJava
Cero.app()
     .messages(Messages.from("mensajes", "en", "qu").base("es"))
     .start();

Los idiomas hay que nombrarlos. El classpath no se puede listar de forma fiable cuando la aplicación va dentro de un jar, así que descubrirlos solos funcionaría en desarrollo y fallaría justo al desplegar.

En un controladorJava
public Object saludar(Context ctx) {
    return Result.text(ctx.t("saludo", nombre));   // «Hola, Richar»
}

El idioma sale de Accept-Language, y se respeta el factor de calidad: fr;q=0.2,qu;q=0.9 responde en quechua aunque el francés vaya primero. Un idioma regional cae en su idioma —es-PE usa es—. Para fijarlo a mano, ctx.idioma("en").

En las plantillas

El mapa t llega solo. No hay que meterlo en el modelo de cada controlador, y esa es la razón de que exista como global: olvidarlo en uno solo dejaría esa página sin traducir y nadie lo vería hasta que se quejara un usuario.

plantilla.htmlPlantilla
<button>{{ t.guardar }}</button>

Si el modelo trae una clave con el mismo nombre que un global, gana el modelo. Al revés, añadir un global nuevo taparía en silencio un dato de una plantilla que ya funcionaba.

Por qué no ResourceBundle

ResourceBundle cae al idioma del sistema cuando no encuentra una clave. Eso hace que el mismo despliegue responda distinto según cómo esté configurado el servidor: un fallo que no se reproduce en la máquina de nadie. Aquí la cadena de respaldo está escrita —idioma pedido, idioma base, la propia clave— y es igual en todas partes.

Un texto que falta devuelve la clave y no lanza: una página a medio traducir sigue sirviendo. Pero avisa por consola una vez por clave, no en cada petición.

Zonas que se repintan solas

Marca una zona en la plantilla y el servidor la vuelve a pintar cuando quiera, sin que escribas una línea de JavaScript.

plantilla.htmlPlantilla
<div data-live="carrito">
  {{ include "carrito.html" }}
</div>
<script src="/cero/live.js"></script>
Desde cualquier punto del servidorJava
Live live = Live.enabled();

Cero.app()
     .views(plantillas)
     .live(live)          // necesita views() antes
     .start();

live.push("carrito", "carrito.html", modelo);
Lo que viaja por el cable es HTML, no JSON

Ese es todo el motivo de que esto exista. El navegador no tiene que saber pintar nada, así que no hay una segunda copia de tus plantillas escrita en JavaScript que se desincronice de las de verdad. La plantilla es una y vive en el servidor.

El cliente son cuarenta líneas que sirve el propio framework en /cero/live.js. Sin paso de compilación, sin node_modules, sin nada que instalar.

  • Sin nadie mirando, no se rinde. Pintar una plantilla para descubrir después que no había destinatarios es trabajo tirado, y en una tarea que empuja cada segundo se nota.
  • Reconecta solo, con espera creciente hasta 15 segundos. Una conexión que se muere en silencio es peor que no tenerla: la página se queda enseñando datos viejos sin decirlo.
  • El canal solo empuja. Lo único que el navegador manda son los nombres de las zonas que tiene en la página. No acepta órdenes.
  • live.pushHtml(zona, html) manda HTML ya hecho, si lo construyes por tu cuenta.

Quién puede escuchar una zona

El nombre de la zona lo manda el navegador, porque el servidor no sabe qué hay pintado en esa página. Mientras la zona lleve lo mismo para todos —un marcador, una cotización, el estado de una cola— eso es justo lo que quieres. En cuanto lleve datos de una sola persona, hace falta decir quién puede oírla: un nombre como pedidos-42 se adivina.

Zonas privadasJava
Live live = Live.enabled().autorizar((peticion, zona) -> {
    if (!zona.startsWith("pedidos-")) {
        return true;                      // zonas públicas, para todo el mundo
    }
    var sesion = peticion.session(false);
    return sesion != null
        && zona.equals("pedidos-" + sesion.get("usuario"));
});

El guardia se consulta una vez por zona y por conexión. Una zona rechazada no se da de alta y el socket sigue abierto con las demás: perder una zona no tiene por qué romper la página entera.

  • Solo el mismo origen. El apretón de manos compara Origin con Host. Sin eso, otra web abriría este canal con la cookie de sesión de quien la visite. Si el frontend vive en otro dominio, o un proxy reescribe Host, decláralo con live.origenes("https://panel.ginit.dev").
  • Topes por conexión. Hasta 32 zonas y 64 caracteres por nombre. Una página real tiene tres o cuatro; el tope está para que nadie llene la memoria del servidor inventando nombres.
  • El mapa vuelve a cero. Cuando se va el último oyente, la zona desaparece del servidor en vez de quedarse como un conjunto vacío para siempre.

No son lo mismo, y confundirlos hace daño

Un proceso puede estar vivo y no poder atender: la base de datos no responde, un servicio del que depende está caído. Si el supervisor reinicia por lo que solo era una base de datos lenta, cambia un problema pasajero por una caída. Y si nunca reinicia, un proceso colgado se queda colgado.

Por eso /cero/vivo no admite comprobaciones: si aceptara una, dejaría de medir lo que dice medir.

/cero/listo responde 503, no un 200 con un cuerpo que dice «mal»: los supervisores miran el código, no el cuerpo. Una comprobación que lanza cuenta como fallo y su mensaje va dentro — tragarse la excepción dejaría un «no listo» sin explicación justo cuando hace falta.

Si la ruta se sirve a internet

Ese detalle es exactamente lo que quieres en una red interna y exactamente lo que no quieres a la vista de cualquiera: el mensaje de un fallo de conexión lleva dentro el host y el puerto de tu base de datos. Con publico() queda el código y el estado, nada más.

ExpuestoJava
Cero.app()
     .health(Health.checks().publico()
         .ready("bd", () -> db.ping()))
     .start();

// 503 con {"estado":"no listo"} — sin nombres ni mensajes

Lo mejor sigue siendo no publicarla: si el supervisor vive en la misma máquina, un deny en el proxy para /cero/listo te deja el detalle entero y no se lo da a nadie más.

Entradas de fuera

Casi nunca hace falta nada: las plantillas escapan por defecto. Un {{ comentario }} con <script> dentro sale como texto visible, no como guion. Para no escapar hay que pedirlo a propósito, con {{ & contenido }}, y ahí empieza tu responsabilidad.

PlantillaPlantilla
{{ comentario }}      // escapado, es lo normal
{{ & comentario }}    // crudo: solo si ya lo limpiaste

Cuando el usuario tiene que poder escribir en negrita

Un comentario, una descripción, un texto de un editor enriquecido: quieres conservar <b> y <a> y quitar todo lo demás. Eso es Sanitize.

ControladorJava
String limpio = Sanitize.html(ctx.form("comentario"));
String resumen = Sanitize.text(limpio);            // sin ninguna etiqueta
String archivo = Sanitize.filename(parte.filename());
Nada de la entrada llega a la salida tal cual

Es lo que separa esto de un filtro. La versión anterior quitaba lo peligroso con expresiones regulares y dejaba pasar el resto; eso es una lista negra, y una lista negra de HTML siempre tiene un agujero más. El que la tumbó fue <svg/onload=alert(1)>: el patrón que borraba los manejadores exigía un espacio antes de on…, y una barra no lo es, así que la etiqueta salía intacta.

Ahora se lee la entrada, se reconoce lo que hay y se vuelve a escribir la salida desde cero. Un atributo que no está en la lista no se examina para ver si es peligroso: no se emite. Por eso onload sobra tanto si va tras un espacio como tras una barra, tras un salto de línea o entre comillas.

EntraSale
<p>hola</p><p>hola</p>
<svg/onload=alert(1)>nada
<script>alert(1)</script>nada, contenido incluido
<desconocida>texto</desconocida>texto
<a href="jav&#97;script:x">t</a><a>t</a>
<p>sin cerrar<p>sin cerrar</p>
  • Las direcciones se juzgan como las leerá el navegador. Primero se deshacen las entidades y se quitan los caracteres de control: jav&#97;script: y java&#9;script: son javascript: en cuanto el navegador los lee, y los dos se caen. Pasan http, https, mailto, tel y cualquier ruta relativa.
  • Los enlaces salen con rel="nofollow noopener noreferrer". Un enlace que viene de fuera no presta la reputación del sitio ni entrega el window.opener de nadie.
  • La salida siempre cierra. Lo que quede abierto se cierra al final y un cierre huérfano se descarta: una entrada rota no puede comerse el resto de la página.
  • Sanitize.text(…) no deja ninguna etiqueta. Es lo que quieres para un resumen, un asunto de correo o un índice de búsqueda.
  • Sanitize.filename(…) se queda con la última parte de la ruta: ../../etc/passwd es passwd.

Y para el resto de la entrada —longitudes, formatos, rangos— está la validación, que es donde debe estar: lo que no cumple no llega al controlador.
